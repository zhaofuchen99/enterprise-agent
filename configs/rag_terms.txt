# 手工业务术语表（详细设计 11.6.2「业务自定义词典」的第 3 个来源）
#
# 这里只放**自动来源覆盖不到的复合术语**。自动来源有两个，见 scripts/gen_dict.py：
#   1. 业务库维度表取值（区域 / 渠道 / 产品线 / 品类 / 产品名）—— 这些是完整取值集，
#      按规则全收，不做取舍；
#   2. `schema_catalog.yaml` 的指标名与别名（净销售额、目标达成率…）。
#
# 本文件承担的是剩下的那一类：**由业务语境拼出来、词典里哪一处都不单独存在**的词。
# 判据不是"我觉得它是术语"，而是"jieba 通用词典会把它切错，且切开以后检索会失准"。
# 生成器会逐条回读验证：加载词典后仍切不出来的条目**直接报错退出**，
# 通用词典本来就能切对的条目**也从产物里剔除**（死词条不该占着位置）。
#
# 所以本表里不应出现「同比」「环比」「毛利率」这类词——通用词典已经切得对，
# 尽管详细设计 11.6.2 把它们列为指标名的例子。设计那句话要的是"指标名被覆盖"，
# 覆盖已经由上面第 2 个来源达成，再往本表抄一遍只是重复。
#
# 省份同理：详细设计提到"下属省份简称"，但业务库**没有省份维度**
# （`dim_region` 只有 `province_count` 这个计数列），MD-008《区域划分与省份归属说明》
# 也明写"区域维度统计一律以区域编码为准，不以省份名称字符串匹配"。
# 少数几处出现的省份名（上海/江苏/浙江）在通用词典里本来就是完整词，
# 收进来是死词条。**故不收**——这不是漏做，是来源本身不成立。

# ------------------------------------------------------------- 指标口径术语
#
# 「净销售额」是最典型的一条：切出来是 `净 / 销售额`，而 `净` 是单字非 ASCII，
# 会被分词器丢弃——结果「净销售额」与「含税销售额」在稀疏路上**撞成同一个 token**。
# 这正是 11.6.2 要避免的精确性丢失，也是 16.11.2「报告数字与 DB 数字差异」
# 那类缺陷能被比对的前提。
#
# **但「净销售额」不写在本表里**：它已经是 `schema_catalog.yaml` 的指标名，
# 由第 2 个来源自动覆盖（`目标净销售额`、`订单行数`、`可用库存` 同理）。
# 本表只收指标目录里没有、却同样会被切错的复合词——
